# CLAUDE.md — content-hub-service

The content hub's backend. Design and the reasons behind it: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Usage:
[README.md](README.md).

## Invariants

- **No operator data in this repository.** Host names, channel ids, handles, roadmap wording and plans belong to
  an operator's private deployment repository. Examples use `example.org` / `<human zone>` placeholders. The generic
  platform definitions (`seed/`) describe platforms, never an operator's destinations.
- **No JavaScript/TypeScript backend.** The service is Rust. TypeScript appears only in `tests/contract` (CI tooling
  that runs the published `@meddleware/content-hub-client` against the built binary).
- **Process and role separation.**
  - `public` runs as the read-only role, which has privileges on schema `public` only: it can read the
    `public_v1_*` views and the migrations table and nothing in `hub`. Public responses are built only from those
    views.
  - `admin`, `worker`, `seed` and `export-snapshot` run as the writer: DML on `hub`, no DDL, no `TRUNCATE`.
  - Only the `migrate` Job runs as the owner. No other process migrates.
  - The admin and public routers take different state types; a handler for one cannot be mounted on the other. Every
    route is in `crates/api/src/routes.rs`; the router tests and the contract job prove each process serves exactly its
    table.
- **Schema identity.** `crates/store/migrations/` is the schema. A released migration is never edited (SQLx records
  its checksum); a change is a new file that keeps the previous release's queries working. `SCHEMA_VERSION` is the
  newest migration. A database migrated by a newer build is refused.
- **Enumerations in three places agree.** The CHECK lists in the migrations, the `ALL` lists in
  `crates/core/src/model.rs` and `vectors.json` (the client's file): `store::tests` compares the first two,
  `core::vectors_tests` the last two. Change all three together, plus the client.
- **Public exposure is a decision.** The columns of every public view are pinned by
  `store::tests::public_view_columns_are_exactly_the_documented_ones`. Adding one means changing the view (a new
  migration), that list, the response type and ARCHITECTURE.md §6 together. Public identifiers are `public_id` UUIDs;
  internal keys never leave the database through a public view.
- **At most once.** An instance is set to `sending` and committed before any external call; `unknown` is never retried
  automatically; only the worker enters `sending`; `posted` is terminal (`crates/core/src/instance_state.rs`, tests
  enumerate every triple). At most one live instance exists per post and target (unique index).
- **Secrets by name only.** `platform_targets.secret_ref` holds an environment-variable NAME starting with
  `PLATFORM_`; the database refuses anything else, and the worker reads no other name. Tokens and webhook URLs are
  never logged, stored or returned (dry runs, attempts, excerpts and reasons are redacted or scrubbed).
- **Validated payloads only.** Nothing reaches `queued` without a payload rendered and checked by
  `crates/api/src/admin/prepare.rs` (enqueue and every operator re-queue); the worker sends that stored payload and
  nothing else.
- **The snapshot is deterministic and its signer holds nothing.** `core::snapshot` makes canonical JSON (sorted keys,
  integers only, ≤ 1 MiB) and signs it as a Sui personal message; `tests/contract/snapshot-fixture.json` (signed by a TEST
  key) is regenerated by `cargo run -p content-hub-core --example gen-snapshot-fixture`, must equal what the code
  produces, and is verified with `@mysten/sui` in CI. The signer key signs only; the Walrus publisher (not the hub) holds
  the float; mainnet exports are refused unless `SNAPSHOT_ALLOW_MAINNET=1`. The hub's client for the publisher may call
  only its configured host.
- **Nothing is sent by default.** A real send needs `PUBLISHING_LIVE=1`, the target's `live`, and production or a
  sandbox target; otherwise the worker records a dry run. The worker's HTTP client connects only to public addresses
  it resolved itself (`crates/publish/src/net.rs`); pure platform rules live in `crates/core/src/platform/`.
- **Costs are capped before they are spent** (ARCHITECTURE.md §2 "Cost caps"); every paid path defaults to 0.
- **Database TLS is `verify-full` only.** `ALLOW_INSECURE_DATABASE=1` is for local tests. The URL and password never
  appear in logs, errors or `Debug` output.
- **No SQL outside `crates/store`.** Dynamic SQL needs SQLx's `AssertSqlSafe` and a reason; prefer bound parameters.
- **One text engine.** Rendering and counting in `crates/core/src/text` are authoritative; the client's TypeScript
  port must reproduce `vectors.json` (offsets in Unicode code points). Enqueue validates every payload with it.
- **No `unsafe`**, no `unwrap`/`expect` on request paths; release builds keep overflow checks and abort on panic.
- **Lean.** SQLx (Postgres only), axum, tower, clap, tracing. One TLS stack: rustls with ring. JWT verification uses
  ring's RSA verifier (not `jsonwebtoken`: its backends are aws-lc-rs or the advisory-flagged `rsa` crate).

## Tests

`SQLX_OFFLINE=true cargo test --workspace --locked` with `TEST_DATABASE_URL` set (a superuser URL;
`scripts/test-postgres.sh` starts a pinned PostgreSQL 18 with TLS). Each database test creates its own database with
the three production roles (`crates/store/src/testdb.rs`); without the variable the tests print `SKIPPED`, and CI sets
`REQUIRE_TEST_DATABASE=1` so none can be skipped there.

- **core** — enumerations (spelling, serde), both state machines against their documented tables, identifier shapes,
  the generic platform definitions, seed validation, the text engine (renderers, counters, segmentation, intent links;
  property tests on arbitrary Unicode), the shared vectors (the committed file equals the generated one).
- **store** — connection settings (TLS required, nothing prints the password), migrations (once, racing, newer schema
  refused, edited migration refused, data schema created when provisioning did not), roles (read-only sees only the
  views; the writer cannot change the schema; append-only tables), constraints, enumeration parity with the CHECK
  lists, public view columns and visibility rules.
- **publish** — every publisher against a local mock: success, refusals, 429, 5xx, a timeout after sending, a
  connection never made, credential hygiene; the checked client refuses private and plain targets; the documented
  OAuth 1.0a signature.
- **worker** — against PostgreSQL and mocks: dry runs, `sending` committed before the call (the mock reads the row),
  retries and the bound, `unknown` never reclaimed, spend settle/release, the janitor and late results, exclusive
  claims, stops, the daily limit, the stop switch, sandbox-only outside production, metrics, alerts, Mastodon limits,
  and one end-to-end run through the admin API, the worker and the public feed.
- **snapshot** — canonical JSON, the signature against the Sui SDK, the export against PostgreSQL and a fake blob store
  (content, determinism, the interval and renewal rules, a failed store records nothing, the lock), no internal wording in
  the signed bytes; the publisher client against a mock (raw body, token bound to the blob, refusals).
- **api** — route exposure (each router answers its table and 404s the other's; public refuses write methods), probes,
  the auth matrix (no token / bad aud, iss, exp / unknown key → 401; non-member → 403; bad CSRF or Origin → 403; Keto
  down → 503), handlers against a real database (CRUD, the task and instance transitions, enqueue validation, the
  audit log), public DTO key snapshots (no internal field), ETag/304, URL validation, the OpenAPI covering every route,
  paid enqueue under and over the caps, re-queue re-validation, the host rules for worker-called URLs, the stop
  switch.

CI also runs the SQLx metadata check, cargo-deny, the SBOM gate, MSRV (1.94), the client contract, a Trivy
configuration scan, the licence notices, the image build and scan, and `scripts/smoke.sh`.

## Release

`docker-publish.yml` on a `v*` tag: the full `rust-ci.yml`, then native per-architecture builds (amd64 on
`ubuntu-latest`, arm64 on `ubuntu-24.04-arm`, never QEMU) to OCI archives without registry credentials, publish per
architecture, merge the index, Trivy by digest, sign, attest (image SPDX, the binary's CycloneDX, build provenance),
`mirror-private` by digest. A manual run is a dry run. The first release needs `@meddleware/content-hub-client`
published first (the contract job installs it; generate `tests/contract/package-lock.json` then).
